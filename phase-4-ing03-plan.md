# Implementation Plan — Structural Document Parsing & Table Preservation (ING-03)

Build and integrate the primary document parsing engine for the **corpus-analyst** platform (**`ING-03`**), enabling structural partitioning of multi-domain documents via `unstructured`, preserving document titles and section hierarchies (`Item 1A - Risk Factors`, `Item 7 - MD&A`, Book Chapters), and preserving tabular structures as explicit HTML/text representations (`is_table = true`) mapped into standardized `Chunk` data contracts.

---

## 1. Architectural Overview & Design Decisions

### 1.1 Structural Document Partitioning (`unstructured`)
- Multi-format ingestion support:
  - **HTML (`.htm`, `.html`)**: Uses `unstructured.partition.html.partition_html` with table extraction enabled. Specifically optimized for SEC EDGAR filings (`10-K`, `10-Q`, `8-K`) and web documents.
  - **PDF (`.pdf`)**: Uses `unstructured.partition.pdf.partition_pdf` or `unstructured.partition.auto.partition` (supporting text and layout extraction).
  - **Text (`.txt`)**: Uses `unstructured.partition.text.partition_text` for raw books, transcripts, and notes.
  - **JSON (`.json`)**: Extracts structured textual fields or serializes structured records into narrative chunks.
- Fault-tolerant parser: Corrupted, unreadable, or empty files raise `DocumentParsingError`, which the `LifecycleManager` intercepts to trigger dead-letter archiving (`/data/failed/*.error.json`).

### 1.2 Section Hierarchy & Context Tracking (`SectionTracker`)
- Documents often lack explicit hierarchical metadata per element. A stateful `SectionTracker` inspects elements as they are partitioned:
  - **SEC EDGAR Sections**: Matches standard 10-K/10-Q headers using robust regexes:
    - `Item 1. Business`, `Item 1A. Risk Factors`, `Item 1B. Unresolved Staff Comments`
    - `Item 2. Properties`, `Item 3. Legal Proceedings`
    - `Item 7. Management's Discussion and Analysis of Financial Condition and Results of Operations` (MD&A)
    - `Item 7A. Quantitative and Qualitative Disclosures About Market Risk`
    - `Item 8. Financial Statements and Supplementary Data`
    - `Item 9A. Controls and Procedures`
    - `Part I`, `Part II`, `Part III`, `Part IV`
  - **Literature / Generic Documents**: Matches structural chapters and sections:
    - `Chapter \d+[:\s\-\.]*.*`, `Prologue`, `Epilogue`, `Introduction`, `Preface`, `Part \d+`
- **Context Cascading**: Once a section header is detected, all subsequent elements (narrative text, list items, tables) inherit this active `section` until a new section header is identified. If no header has appeared yet, elements default to `"General"` (or the document title).

### 1.3 Tabular Structure & HTML Preservation
- Tabular data in financial reports (balance sheets, income statements, segment metrics) must retain exact layout and row/column associations:
  - When `unstructured` identifies a `Table` element, it populates `element.metadata.text_as_html` containing verbatim `<table>...</table>` markup.
  - For tabular chunks:
    - `is_table = True`
    - `text`: Assigned the verbatim HTML table string (falling back to cleaned plain text if HTML was not extracted).
    - `metadata["table_html"]`: Stores the raw HTML table string.
    - `metadata["element_type"]`: Marked as `"Table"`.
  - Non-tabular elements:
    - `is_table = False`
    - `text`: Cleaned narrative text string.
    - `metadata["element_type"]`: e.g. `"NarrativeText"`, `"Title"`, `"ListItem"`.

### 1.4 Metadata Propagation & Companion Sidecars
- When parsing a file (e.g. `NVDA_10-K_20240221.htm`):
  - Checks for companion `.meta.json` sidecar files (generated by SEC fetcher or UI ingestion).
  - Extracts `doc_id`, `domain`, `form_type`, `filing_date`, `ticker`, and `company_name`.
  - If no sidecar exists: Computes a deterministic `doc_id` via SHA-256 hash of file content and infers `form_type` and `domain` from filename heuristics.
  - Every emitted `Chunk` carries these parent metadata fields, ensuring complete traceability.

### 1.5 Token Count Estimation (`estimate_token_count`)
- Calculates deterministic token estimates:
  - Word count + punctuation heuristic ($\approx 1.33 \times \text{word count}$ or $\lceil \text{chars} / 4 \rceil$).
  - Enables `Chunk.token_count` population and provides the evaluation metric needed by Phase 4 `ING-04` (recursive token splitting when `token_count > max_chunk_tokens`).

### 1.6 Lifecycle Integration (TREM: Extensible)
- `DocumentParser` in `src/ingestion/parser.py` implements `DocumentProcessorProtocol`:
  ```python
  def process(self, file_path: Path, metadata: DocumentMetadata | None = None) -> IngestionResult
  ```
- Generates `Chunk` objects, calculates `chunk_count` and `token_total`, logs processing telemetry, and returns an `IngestionResult` envelope.
- Plugged into `LifecycleManager(processor=DocumentParser())` to replace the lightweight Phase 3 `DefaultDocumentProcessor`.
